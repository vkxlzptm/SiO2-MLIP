## 1. 왜 만드나 (맥락)

- 2026-08-03 **코닝 전화 인터뷰**. 분자모델링 파트 리더가 **MLIP가 현재 최대 관심사**이고
  **유리 특화 MLIP 개발을 검토 중**이라고 말했다.
- 통화에서 사용자가 "SevenNet-Nano 테스트 프로젝트를 해볼 계획"이라고 언급했고,
  실제로 **4일(8/10~8/13, git 기록 기준)** 만에 수행했다.
- 이 PPT는 **그 약속을 닫는 후속 송부물**이다. 과제 제출물이 아니라 "말한 걸 했습니다"에 가깝다.

**수신**: 분자모델링 파트 리더에게 **직접 송부. 윤홍 그룹장 cc 하지 않음** (사용자 결정).

**톤**: 자랑이 아니라 **실무자가 실무자에게 보내는 짧은 기술 메모**. 실패와 한계를 숨기지 않는 게
이 자료의 강점이다 (아래 §4 참고).

## 4. 반드시 조심할 함정 (전부 실제로 한 번씩 틀렸던 것들)

### 4-1. K₀ 비교 — "BKS가 더 정확하다"고 쓰면 틀린다

BKS 34.3 vs 7net 43.2 GPa는 **각자의 평형 밀도에서 읽은 값**이라 비교가 성립하지 않는다.
실리카는 K₀′ < 0(**anomalous compression**: 조밀할수록 물러짐)이라 BKS가 6.6 % 더 조밀한
것만으로 K₀가 실험 쪽으로 끌려 내려온다. **같은 밀도에서 보면 두 포텐셜이 3 % 이내로 겹친다.**
그리고 실험 밀도에서는 **둘 다 +20 % 과대**다.

→ 슬라이드 구성: **처음엔 MLIP가 더 틀린 것처럼 보이는 결과를 보여주고, 그 다음 함정을
푸는 순서**로 간다 (사용자 지시). 결론은 "포텐셜 문제가 아니라 **구조 생성 프로토콜** 문제이고,
MLIP로 바꿔도 안 고쳐진다" — 실무자에게 이게 더 쓸모 있는 메시지다.

### 4-2. 속도 비교 — 표현에 주의

- **MLIP가 classical MD보다 10²~10³배 느리다**는 얘기를 반드시 할 것. 유리하게만 쓰지 말 것.
- **"문헌 통상 10²~10³배" 같은 근거 없는 문장을 쓰지 말 것.** 과거에 지어냈다가 걸렸다.
  인용은 SevenNet 논문의 실제 teacher 대비 속도 향상값 + 우리 자체 측정만 쓴다.
- 배수는 조건 의존이 심하다: 같은 두 포텐셜인데 **2,462배**(cutoff 5.5, ρ=2.607)와
  **1,244배**(cutoff 4.5, ρ=2.20)가 둘 다 사실이다. **조건을 반드시 함께 적을 것.**
- `fig_speed.png` (b)의 x축 라벨은 `number of threads / processes`.

### 4-3. 밀도 숫자 혼선

**ρ = 2.20 계열(현행)만 쓴다.** BKS 2.3442 / 7net 2.2185.
**ρ = 2.607은 폐기된 v1**이다. 속도 비교 데이터 일부가 v1 조건에서 나왔으므로,
그 수치를 쓸 때는 조건을 명시하거나 현행 값으로 통일할 것.

### 4-4. melt-quench 실패의 정확한 서술

**"녹지 않았다"가 아니다.** 늦게 녹았고, **녹는 순간 NPT 때문에 부피가 붕괴**(2.26 → 2.62)한 것이다.
정확히는 "용융 중 NPT 사용"이 원인이다.

### 4-5. AIMD 참조값

Dechant et al., JPCC 2026 (published, PBE). **셀이 120원자 · L = 12.2 Å**로 작고
quench가 5 ps(≈4×10¹⁴ K/s)로 우리보다 100배 빠르다.
→ **"7net이 DFT보다 정확하다"고 쓰지 말 것.** 방어 가능한 문장은
*"이 조건의 AIMD 참조값보다 실험에 가까웠고, 그 차이는 참조 계산의 유한크기·급냉으로 설명 가능"*.
유한크기 한계를 슬라이드에 담을지는 사용자에게 확인할 것 (이전에 물었으나 미결).

### 4-6. PBE underbinding과 어긋나 보이는 결과

Si–O 결합이 늘어나는 건 PBE underbinding으로 설명되지만 K₀는 반대 방향으로 보인다 —
이건 4-1의 밀도 혼동 때문이다. **"counter-intuitive하다!"를 전면에 내세우지 말 것.**
비정질 망 구조를 모르는 사람처럼 보일 수 있다는 사용자 우려가 있었다.

## 5. PPT 작업 **전에** 끝내야 할 것 — 출처 조사

사용자가 "PPT 구상이 끝난 후 진행"으로 미뤄둔 항목이다. **슬라이드에 실험값을 적는 이상
출처 없이 쓸 수 없다.** 구성 확정 직후, 슬라이드 채우기 전에 처리할 것.

| 값 | 현재 상태 |
|---|---|
| ρ_exp = 2.20 g/cm³ | 출처 미확인 |
| K_exp = 36.7 GPa | 출처 미확인 |
| Si–O 1.610 Å, O–O 2.630 Å, Si–Si 3.080 Å | 출처 미확인 |
| Si–O–Si 140~150° | 출처 미확인 |
| FSDP (위치·높이) | Zeidler PRL **113**, 135501 (2014) — **확보됨** |
| a-SiO₂의 문헌 DFT/AIMD K₀ (최근 10년 내) | 미조사 |
| GGA의 탄성계수 경향 (과소/과대) 검증 | 미조사 |

**arXiv 전용·피인용 적은 논문은 신뢰하지 말 것.** 출판·피인용 있는 문헌을 우선한다.

   오간다. 추가 MD 없이 E–V 스캔 구조에서 결합길이·각도를 직접 재면 됨.
3. (선택) excess energy — α-quartz 단일점 하나, 7net으로 1분.
4. (선택) 7net 어닐링 — 중거리 구조를 마저 고치려면 필요. 20 ps에 11시간.
5. **별건 플래그**: Cu 증착 프로젝트의 `CLAUDE.md` §1.2가 ρ=2.607을 10 Å cutoff 탓으로

## 7. 사용자 작업 규칙 (계속 적용)

- **계산량 큰 작업은 착수 전 예상 소요시간을 알리고 확인받을 것.**
- **에이전트를 많이 쓰는 작업은 사전 확인.** 사용자가 직접 한두 번 클릭으로 되는 일에
  토큰·시간을 쓰지 말 것.
- **검증 안 된 수치를 지어내지 말 것.** 문헌값은 출처와 함께, 불확실하면 불확실하다고 명시.
- **사용자의 가설도 데이터로 반증되면 그대로 말할 것.** 좋은 결과가 나오도록 유도하지 말 것.
- 각 실행마다 `02_run/*/NOTE.md`에 조건·이유·결과를 한 줄씩 기록.
- DFT/물리 개념 설명은 생략 가능. **MLIP 툴체인 쪽은 짚어줄 것.**
- 원격 실행 명령은 **복붙 가능한 형태**로 줄 것 (사용자가 결과를 붙여넣는다).
- 답변은 간결하게.
- **파일 관리**: 샌드박스는 파일 삭제 불가, git 직접 실행 시 `.git/*.lock`이 남는다.
  → **Claude는 파일을 쓰기만 하고, `./sync.sh`와 `./cleanup.sh`는 사용자가 실행한다.**
